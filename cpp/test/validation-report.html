같은 WAV에서 ‘ah’가 달랐던 이유

기존 Python 실행은 발화 전체에서 특징을 계산한 뒤 프레임을 나누고, 별도로 추출한 300 ms 무음 특징을 이어 붙였다. C++은 입력 파형을 청크별로 특징화하고 마지막 오디오 버퍼에 500 ms 무음을 붙인다. 입력을 나누는 시점이 달라 경계 프레임과 인코더 입력이 달라진다. C++의 최종 CTC 탐색도 greedy이므로 비교 모드에서 이 조건까지 맞췄다.

--cpp-runtime과 셸 실행 스크립트는 16 kHz 입력, 1.5초 청크, 마지막 파형의 8,000샘플 무음, attention beam 3을 사용한다. 기존 발화 단위 실험은 Python CLI에서 이 옵션을 생략해 재현할 수 있다. 첫 번째 Stanford WAV에서 CTC는 양쪽 모두 i'm honored …, 2차 전사는 양쪽 모두 i'm ah honored …였다. Python 추론 경로

전체 목록에서 발견한 두 번째 차이

22번 WAV에서는 같은 인코더 출력을 사용해도 C++이 couldnt, Python이 couldn't를 선택했다. 같은 PyTorch 모델에 기존 C++의 종료 후보 큐 처리를 적용해 couldnt를 재현했다. 두 방식은 종료된 가설이 다음 단계의 빔 폭을 차지하는지, 언제 탐색을 끝내는지가 달랐다.

C++ 2차 디코더에서도 진행 중인 가설과 종료된 가설을 누적 로그 확률로 함께 정렬해 상위 후보를 보존하고, Python처럼 2차 인코더 프레임 수로 탐색 길이를 제한했다. 해당 WAV를 다시 실행했을 때 두 결과 모두 after six months i couldn't see the value in it였다. 스트리밍 디코더

현재 작업공간 재검증

Linux와 JDK 17에서 cpp/export와 cpp/test/api_test의 기본 빌드 전체가 성공했다. 배포용 libasr_api.so를 Java에서 직접 로드해 첫 번째 Conan 음성을 입력했고, onResult가 before i begin을 받았다. 통합 검사 50개와 CTest 3개가 다시 통과했다. 같은 체크포인트로 WAV 143개의 특징을 양쪽에서 독립적으로 추출했을 때 CTC와 attention 전사가 각각 143개 모두 일치했다.

  • 현재 model/sample_model에는 학습 가중치가 없어 MODEL_PATH를 생략하면 Python 추론이 FileNotFoundError로 종료된다. 아래 재현 명령의 체크포인트 경로를 지정하면 같은 WAV에서 추론이 완료된다.
  • 발화 종료 진단 도구는 기본 100ms로 실행해 최종 전사를 반환했다. 소스 검토에서 chunk_ms에 0 또는 숫자로 시작하지 않는 문자열을 주면 청크 크기와 읽기 위치의 증가량이 모두 0이 되는 문제를 확인했다. 진단 도구 소스

이번 검증은 로컬 Linux에서 실행했다. Android와 iOS 실기기는 검증 범위 밖이다. 검증 시점에 cpp/는 Git 미추적 상태였다.

재현 명령

저장소 루트에서 실행한다. 검증 환경은 GCC 9.4, CMake 3.30.2, JDK 17.0.2, PyTorch 2.10 CPU 추론이다. 아래의 JDK 경로는 이번 머신 기준이다.

export JAVA_HOME=/usr/local/jdk-17.0.2
export PATH="$JAVA_HOME/bin:$PATH"
export OMP_NUM_THREADS=2
export CMAKE_BUILD_PARALLEL_LEVEL=4
build=$(mktemp -d)
export MERCURY_TEST_BUILD_ROOT="$build"

cmake -S cpp/export -B "$build/export" -DCMAKE_BUILD_TYPE=Release
cmake --build "$build/export" --target asr_api
bash cpp/test/run_all_tests.sh --continue
cmake --build "$build/api" --target recognition_score_test stability_test
ctest --test-dir "$build/api" --output-on-failure
cmake -S cpp/score -B "$build/score" -DCMAKE_BUILD_TYPE=Release
cmake --build "$build/score" --target scorer_test
ctest --test-dir "$build/score" --output-on-failure

export MODEL_PATH="$PWD/arifact/stream_conformer_mercury3_adapt_1p5s"
export MERCURY_TEST_MODEL_DIR="${MODEL_PATH}_cpp_export"
export MERCURY_COMPARE_OUT="$build/wav-results"
bash cpp/test/api_test/run_api_test.sh compare
bash model/stream_conformer_infer.sh \
  cpp/test/resource/StevJobs_Standford/processing/SteveJobsStanford00001.wav
독립 특징 추출로 143건을 다시 대조하는 명령
PYTHONPATH=model python3 - <<'PYTHON'
import os
from itertools import groupby
from pathlib import Path
from util.stream_conformer_inference import StreamConformerInference
m = StreamConformerInference.from_model_path(os.environ["MODEL_PATH"])
dump = Path(os.environ["MERCURY_COMPARE_OUT"])
listing = Path("cpp/test/api_test/wav_local.list")
matched = [0, 0]
files = [listing.parent / line for line in listing.read_text().splitlines() if line.strip()]
for wav in files:
    py = m.transcribe_wav_file(str(wav), chunk_duration_ms=1500, beam_size=3, cpp_runtime=True)
    lines = (dump / (wav.stem + ".ids.txt")).read_text().splitlines()
    ctc_ids, attn_ids = [list(map(int, line.split())) for line in lines]
    ctc = [token for token, _ in groupby(ctc_ids) if token != m.wrapper.blank_id]
    matched[0] += py["ctc2_text"] == m.decode_token_ids_to_text(ctc)
    matched[1] += py["attention_text"] == m.decode_token_ids_to_text(attn_ids)
print("WAV / CTC / attention:", len(files), *matched)
assert matched == [len(files), len(files)]
